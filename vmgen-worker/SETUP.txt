VMGen Worker - Setup Instructions
===================================

1. CREATE VIRTUAL ENVIRONMENT
   python -m venv .venv

2. ACTIVATE (Windows PowerShell)
   .\.venv\Scripts\Activate.ps1 (python -c "import sys; print(sys.prefix)")

   If blocked, first run:
   Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

3. INSTALL DEPENDENCIES
   pip install -r requirements.txt

4. TRUST THE PROXMOX HOST KEY (one-time)
   The worker verifies the Proxmox host's SSH fingerprint before connecting.
   Run this once on the machine where the worker will run:

   ssh-keyscan -H <PROXMOX_HOST_IP> >> ~/.ssh/known_hosts

   Example for this lab:
   ssh-keyscan -H 172.22.21.95 >> ~/.ssh/known_hosts

   This appends the Proxmox host's public key to your local known_hosts file.
   The worker reads this file at startup (PROXMOX_KNOWN_HOSTS_PATH in .env).
   If the file is missing or the host is not in it, the worker will refuse to start.

   You only need to redo this if the Proxmox host's SSH host key changes
   (e.g. after a full OS reinstall of the Proxmox host).

5. GENERATE SSH KEY FOR PROXMOX HOST ACCESS
   The worker needs SSH access to the Proxmox host to run qm exportovf (OVA export).
   This is separate from the Proxmox API token — it's direct shell access.

   Generate the key pair (press Enter twice for empty passphrase — worker runs unattended):
   ssh-keygen -t ed25519 -C "vmgen-worker" -f "$HOME\.ssh\vmgen_worker"

   Copy the public key to the Proxmox host (enter root password once):
   type $HOME\.ssh\vmgen_worker.pub | ssh root@<PROXMOX_HOST> "cat >> ~/.ssh/authorized_keys"

   Test the connection (should open a shell without asking for a password):
   ssh -i $HOME\.ssh\vmgen_worker root@<PROXMOX_HOST>

   Files created:
   - C:\Users\<you>\.ssh\vmgen_worker      (private key — stays on this machine)
   - C:\Users\<you>\.ssh\vmgen_worker.pub  (public key — copied to Proxmox)

5. CONFIGURE ENVIRONMENT
   - Copy .env.example to .env
   - Fill in your credentials:
     * DATABASE_PASSWORD
     * PROXMOX_HOST, PROXMOX_TOKEN_ID, PROXMOX_TOKEN_SECRET
     * PROXMOX_ISOLATED_BRIDGE (code default: vmbr1 -- must actually point at a bridge/subnet
       genuinely separate from the management/platform network, e.g. vmbr2; same-subnet hosts
       bypass any firewall between them, so this can't just be left at the default)
     * PROXMOX_SSH_KEY_PATH (e.g. C:\Users\whoami\.ssh\vmgen_worker)
     * PROXMOX_SSH_USER (default: root)
     * BACKEND_API_KEY
     * EXPORT_PATH — filesystem path where OVAs are written, must be accessible
       from both the Proxmox host (qm exportovf writes here) and this worker
       machine (to compute SHA-256). Use an NFS mount. (e.g. /mnt/vmgen-exports)
     * VM_SSH_PASSWORD — only needed if any template uses sshAuthMethod=password_reset
     * VM_STATIC_KEY_PATH — only needed if any template uses sshAuthMethod=static_key

6. CONNECT TO DATABASE
   docker exec -it vmgen-postgres psql -U vmgen -d vmgen

7. RUN WORKER
   python -m worker.main

---
TROUBLESHOOTING:

If psycopg2-binary fails to install on Python 3.13:
   pip install psycopg[binary]
   (Note: psycopg3 uses different package name)

Or downgrade to Python 3.11/3.12 for full compatibility.
